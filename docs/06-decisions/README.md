# Architecture Decision Records (ADRs)

ADRs capture important technical and product-architecture decisions, including context, alternatives, consequences, and status.

## When to write an ADR

Create or update an ADR when a decision materially affects architecture, security, data, integrations, deployment, or long-term maintainability. Small implementation choices do not need an ADR.

## Process

1. Create the next numbered file using `ADR-NNNN-short-title.md`.
2. Start with status **Proposed** and discuss it in the linked issue/PR.
3. Once accepted, change status to **Accepted**. Superseded decisions remain in history and link to their replacement.
4. Link the ADR from the relevant technical documentation and PR.

See [template](ADR-TEMPLATE.md) and [decision log](decision-log.md).
