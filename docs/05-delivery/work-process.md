# How we work

## Keep work clear

Every task should explain:

- What needs to be done.
- Why it matters.
- Who will use it.
- What result is expected.
- How we will check that it works.

## Suggested task states

- **Backlog:** Not ready to start.
- **Ready:** Clear and ready to be picked up.
- **In progress:** Someone is working on it.
- **In review:** The work needs checking.
- **Done:** The agreed result has been checked.

## Task checklist

Before starting:

- [ ] The problem is clear.
- [ ] The expected result is written down.
- [ ] The task is small enough to complete.
- [ ] Important design or product decisions are known.

Before marking done:

- [ ] The feature works as expected.
- [ ] Important error cases are handled.
- [ ] Access rules are checked.
- [ ] Tests have been run.
- [ ] Documentation has been updated when needed.

## Writing style

- Use simple English.
- Explain short forms the first time they appear.
- Keep paragraphs short.
- Use examples when they make a rule easier to understand.
- Do not use em dashes.
- Do not claim that an idea is confirmed when it is still an assumption.
